## Decisions Made

- **Throw, not warn.** The plan and 02.1-CONTEXT.md locked this in: Wesley wants build failures, not silent corruption that ships to production. The new `requireFields` helper throws a `new Error` whose message includes the schema name, the offending field name, and `Astro.url?.pathname` so a Vercel deploy log line points at the exact failing page.
- **Validate caller-supplied fields only.** The plan flagged a subtle CR-03 spec issue: the original CR-03 entry mentioned `author.name` and `author.url` as required, but those are component-internal constants pinned to PERSON_ID — never sourced from caller data. Validating them would be dead code. Per the plan's `<behavior>` section, only `headline`, `datePublished`, `description` are caller-required; the helper enforces those three.
- **Symmetric helper instead of two inline guards.** A single `requireFields(name, data, fields[])` is easier to read and extend than two copy-pasted `if (!data.headline) throw ...` blocks. If the Article schema later needs a different required-set than BlogPosting, the call sites diverge cleanly without touching the helper.
- **Helper placement above PERSON_ID.** The plan specified "after line 31 (siteUrl) and before line 33 (PERSON_ID block)" — I followed that, which leaves the helper visually near the other top-of-frontmatter declarations (`siteUrl`, `PERSON`, `WEBSITE`) rather than buried lower in the schema-dispatch chain. Future maintainers see the validation primitive next to the constants it guards.
- **`dateModified` left optional.** BlogPosting's `dateModified` was `(data.dateModified as string | undefined)` already (no `?? ''`), and CR-03 only flagged the three required-on-create fields. Preserved as-is — passing `undefined` for `dateModified` is a valid signal that the post has not been edited since publication.
- **No new tests added.** Existing essays + notes provide implicit positive-path coverage at every build (all 33 pages must construct without throwing). Adding a Vitest unit test for the throw path was out of scope per the plan's task list (no tests requested) and would add a new test surface; the build itself is the regression test.
