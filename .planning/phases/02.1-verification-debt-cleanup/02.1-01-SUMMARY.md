## Decisions Made
- **Targeted regex over broad `<` escape.** Per 02.1-CONTEXT.md locked decision: replace `</script>` (case-insensitive, all occurrences) only. The alternative — escaping every `<` — was rejected because it produces noisier output for no additional safety in the inline-`<script>` JSON context.
- **`/g` and `/i` flags both required.** `/g` to catch multiple occurrences in a single page's JSON; `/i` to catch any case variant (`</Script>`, `</SCRIPT>`, etc.) since HTML parsers are case-insensitive about the closing tag.
- **Added the CR-01 comment line.** The plan made this optional ("if you wish you may add a one-line comment"); I added it for traceability — anyone diffing this file later sees the `CR-01` reference and can find the locked decision in 02.1-CONTEXT.md.
