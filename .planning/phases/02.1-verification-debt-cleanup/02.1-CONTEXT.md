## Implementation Decisions (LOCKED)

### CR-01 — JsonLd.astro `</script>` escape
- **File:** `src/components/seo/JsonLd.astro` line 116
- **Current:** `set:html={JSON.stringify(json)}` — emits raw JSON, vulnerable to script-injection if any frontmatter field contains the literal string `</script>`
- **Fix:** Replace `</` with `<\/` in the JSON output before emitting. Standard pattern: `JSON.stringify(json).replace(/<\/script>/gi, '<\\/script>')` (the `/g` and `/i` flags ensure all case variants are caught). Alternative: replace `<` with `<` (broader but uglier).
- **Decision:** Use the targeted `</script>` regex replace — cleaner output, equally safe.

### CR-02 — NoteLayout dt-published mislabel
- **File:** `src/layouts/NoteLayout.astro` line 59 area
- **Current:** `dt-published` class applied to `displayDate = updated ?? published` — when both `published` and `updated` exist, the `updated` date is incorrectly labeled as the published date in microformats.
- **Fix:** Render TWO `<time>` elements: one with `class="dt-published"` for `published`, one with `class="dt-updated"` for `updated` (only when `updated` is set and differs from `published`). The visible date can still default to `updated ?? published` for human readers.
- **Reference:** Microformats spec — dt-published and dt-updated are distinct properties.

### CR-03 — JsonLd.astro fail-loud on missing fields
- **File:** `src/components/seo/JsonLd.astro` lines 80-103
- **Current:** Required Schema.org BlogPosting fields default to empty string (`?? ''`) if caller omits them — silent corruption.
- **Fix:** **Throw at build time** when required BlogPosting fields are missing. Required fields per Schema.org BlogPosting spec for our use case: `headline`, `datePublished`, `author.name`, `author.url`. Throw with a clear error message identifying the field and the caller.
- **Decision (LOCKED):** Throw, not console.error. Per Wesley: "I don't want things to fail silently."
- **Effect:** Bad frontmatter fails `astro build`, fails Vercel deploy. You fix the frontmatter and redeploy.

### WR-01/WR-02 — relations.ts slug warnings + stop-at-first-hit
- **File:** `src/lib/relations.ts` lines 27-45
- **Current:** Silently emits duplicate entries if a slug exists in both essays and notes collections; silently drops missing slugs.
- **Fix:**
  - Add `console.warn` when a `related:` slug is not found in either collection
  - Add `console.warn` when a slug is found in BOTH collections (emit once per duplicate slug)
  - Stop at first hit per slug — search essays first, then notes; do not double-emit
- **Decision:** `console.warn` (not throw). Build-time warnings are visible in `astro build` output and Vercel logs but don't block deploys for content-authoring nits.

### WR-03 — BaseLayout Umami env URL validation
- **File:** `src/layouts/BaseLayout.astro` lines 88-95
- **Current:** Builds Umami `<script src>` from `PUBLIC_UMAMI_HOST` env var with no URL validation, no trailing-slash normalization. Bad env var produces broken script tag silently.
- **Fix:** **Throw at build time** when `PUBLIC_UMAMI_HOST` is set but malformed (fails `new URL()` constructor). When the env var is unset entirely, skip the Umami script silently (analytics is optional — unset = "no analytics", not an error). When set, normalize trailing slash before building the `src` attribute.
- **Decision (LOCKED):** Throw on malformed-but-present env var (per Wesley: "no silent failures"). Unset is not an error — omitting analytics is a valid configuration.

### WR-07 — tags.ts kebab-case Zod refinement
- **File:** `src/lib/tags.ts` (and/or `src/content.config.ts` schema)
- **Fix:** Add a Zod regex refinement enforcing kebab-case-only tags: `/^[a-z]+(-[a-z]+)*$/` — strict lowercase letters and single hyphens, no digits, no underscores, no leading/trailing hyphens, no double hyphens.
- **Decision (LOCKED):** Strict regex with no digits. Derived from current tags inventory: `ai, analytics, astro, bitcoin, consulting, design, freedom-tech, health, indieweb, open-source, privacy, self-hosting, sovereignty, sovereignty-as-a-service, thesis, tooling, why-astro-over-next, why-self-host-umami, writing` — every existing tag matches `[a-z]+(-[a-z]+)*`. No digit-bearing tags in the corpus.
- **Effect:** A future essay with `tags: [bitcoin-2026]` will fail content schema validation at build time with a clear Zod error.

### IN-02 — Date formatting UTC pin
- **Files:** `src/layouts/NoteLayout.astro` line 41, `src/layouts/EssayLayout.astro` line 40
- **Current:** `d.toLocaleDateString('en-US', { year: 'numeric', month: 'short', day: 'numeric' })` — uses the build environment's local timezone, producing nondeterministic output across machines/CI.
- **Fix:** Add `timeZone: 'UTC'` to the options object: `{ year: 'numeric', month: 'short', day: 'numeric', timeZone: 'UTC' }`.
- **Decision:** Pin UTC. Build output now identical on Wesley's laptop, CI runner, and Vercel build container.
