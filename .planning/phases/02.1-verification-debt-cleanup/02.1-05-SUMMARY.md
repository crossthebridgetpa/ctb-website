## Accomplishments

- Replaced the unguarded `const umamiHost = import.meta.env.PUBLIC_UMAMI_HOST` read with a four-branch guarded read:
  - Unset/empty → `umamiHost` stays `undefined`, three-way JSX guard skips silently
  - Set + parses through `new URL()` → strip trailing slashes via `replace(/\/+$/, '')`, assign normalized form

## Decisions Made

- **Throw at build, do not console.warn or console.error.** Per `02.1-CONTEXT.md` WR-03 locked decision and Wesley's stated principle ("no silent failures"). A typo'd PUBLIC_UMAMI_HOST is a deployment defect — the build SHOULD fail so Vercel does not ship a broken script tag.
- **Unset is not an error.** Phase 01 D-14 explicitly treats unset Umami env vars as "no analytics" — a valid configuration for dev, preview, and any deploy where Wesley wants the site running before the Umami stack is provisioned. Throwing on unset would couple build success to analytics provisioning, which is wrong.
- **Use `new URL()` as the gate, not a regex.** The WHATWG URL parser is the canonical correctness check — it accepts what real browsers accept, rejects what they reject, and is already shipped with Node. A regex would either be too permissive (accepting `umami.crossthebridge.io` without protocol) or too brittle (rejecting valid edge cases).
- **Normalize trailing slashes at the read boundary, not at JSX assembly.** Single source of truth for the shape of `umamiHost`; downstream `${umamiHost}/script.js` stays naive-safe.
