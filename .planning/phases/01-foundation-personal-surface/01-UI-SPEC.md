# Phase 1 — UI Design Contract

> Visual and interaction contract for the Foundation + Personal Surface phase. Generated by gsd-ui-researcher (2026-04-25). Verified by gsd-ui-checker before planner consumes.

This contract translates the locked decisions in `01-CONTEXT.md` into prescriptive design tokens, component specs, copywriting, and accessibility rules. The planner builds plans against this; the executor implements against this; the auditor measures the shipped site against this.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual) |
| Preset | not applicable — single-author site, custom token system, ~5–8 components ceiling |
| Component library | none — author hand-rolled `.astro` components |
| Icon library | `astro-icon` + `@iconify-json/lucide` (tree-shakeable inline SVG, zero JS) — used sparingly: hamburger, RSS, external-link arrow, theme indicator |
| Display font | Playfair Display (weights 400 + 700) — self-hosted via Astro Fonts API + Fontsource provider. NO Google Fonts CDN. |
| Body font | Inter (weights 400 + 600) — self-hosted via Astro Fonts API + Fontsource provider. Variable font preferred (`Inter Variable`). |
| Theme delivery | Tailwind v4 via `@tailwindcss/vite`. Tokens declared in `src/styles/app.css` `@theme` block. Light/dark via `prefers-color-scheme` only — no manual toggle. |

**Network audit invariant (load-bearing):** First paint of every page contacts AT MOST 1 third-party domain (the Umami analytics endpoint). Zero requests to `fonts.googleapis.com`, `fonts.gstatic.com`, `google-analytics.com`, `googletagmanager.com`, `youtube.com`, `youtu.be`, `twitter.com`, `x.com`, `usemotion.com`. CI gate enforces this.

## Spacing Scale

Single 4-point scale, declared once as Tailwind v4 theme tokens. Generous-density (Collison-style): defaults skew toward larger values. Most page rhythm uses `lg`/`xl`/`2xl`; `xs`/`sm` are inline-only.

**Documented standard set: {4, 8, 16, 24, 32, 48, 64, 96}.** The `96px` (`--spacing-4xl`) stop is the one justified extension beyond the canonical 7-stop set {4, 8, 16, 24, 32, 48, 64}. It is required for hero/section breathing room in the generous-density Collison aesthetic; without it, page-level section dividers (e.g., between hero and tile grid) collapse into the 64px rhythm and the page reads dense rather than spacious.

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| `--space-xs` | 4px | `p-1`, `gap-1` | Inline icon gap, badge padding |
| `--space-sm` | 8px | `p-2`, `gap-2` | Compact stack rhythm (between line of meta + body) |
| `--space-md` | 16px | `p-4`, `gap-4` | Default paragraph rhythm, list item gap, CTA vertical padding |
| `--space-lg` | 24px | `p-6`, `gap-6` | Card internal padding, nav link gap, CTA horizontal padding |
| `--space-xl` | 32px | `p-8`, `gap-8` | Card grid gap, section internal rhythm |
| `--space-2xl` | 48px | `p-12`, `gap-12` | Major content section breaks |
| `--space-3xl` | 64px | `p-16`, `gap-16` | Page-level top padding (below nav), hero breathing room |
| `--space-4xl` | 96px | `p-24`, `gap-24` | Page-level section dividers (between hero and tile grid) — justified extension beyond the canonical 7-stop set |

**Exceptions (load-bearing, do not mutate):**
- Touch targets are min 44×44px (WCAG 2.2 AA — `2.5.5 Target Size`). Hamburger toggle, mobile nav links, and the "Get in touch" CTA all meet this — hit-area can extend invisibly past the visible glyph.
- Skip-to-main link occupies a fixed 8px offset from the top-left when focused.

**Layout container:** Single column. Content max-width is `--measure: 65ch` (~640px) for prose; hero and tile grid expand to `--measure-wide: 880px`. No centered-narrow + sidebar variants in Phase 1. Outer page padding: `--space-lg` (24px) on mobile, `--space-2xl` (48px) on ≥768px.

## Typography

**Scale (4 sizes, 2 families, 2 weights per family — tight by design).** Body line-height 1.6 (matches existing site, optimal for cream surfaces); display line-height 1.15 (tight for impact). Letter-spacing negative for display (-0.02em), default for body. The display size is responsive: 56px on ≥768px viewports, clamped to 36px on mobile via a `clamp()` value applied to the `text-display` class — NOT a separate named token.

| Role | Family | Size | Weight | Line height | Tailwind class | Usage |
|------|--------|------|--------|-------------|----------------|-------|
| Display | Playfair Display | `clamp(2.25rem, 5.5vw + 1rem, 3.5rem)` (36px → 56px responsive) | 700 | 1.10 desktop / 1.15 mobile | `text-display` | Hero question line ("What does it look like to opt out…"); About-page H1; project-page H1 |
| Heading | Playfair Display | 28px (1.75rem) | 700 | 1.20 | `text-heading` | Section headings on About/Project pages, project-card titles |
| Body | Inter | 18px (1.125rem) | 400 (prose) / 600 (titles & section labels) | 1.50 (titles) / 1.60 (prose) | `text-body` | Tile-card titles (weight 600), nav-logo wordmark (weight 600), hero supporting copy (weight 400), all prose, project-page subtitles (weight 600) |
| Meta | Inter | 14px (0.875rem) | 400 | 1.50 | `text-meta` | Footer, colophon details, "external link" annotations, dates, nav links |

**Notes:**
- Body unified at **18px** for the generous-density Collison reference. The previous spec split this into 17px body + 18px subheading; the 1px delta wasn't carrying weight — the **600 vs 400 weight contrast already differentiates the roles** (titles & section labels use weight 600; prose uses weight 400). Easier on the eye for long-form thesis copy and reduces token count.
- Display size collapses to 36px on mobile via `clamp()` — no separate `text-display-mobile` token. This keeps the scale at exactly 4 named sizes.
- No Italic Playfair imported in Phase 1 (existing site loaded Playfair italic 400 — saves a font file). Add only if a Phase 2 essay genuinely needs it.
- Inter weight 500 is dropped (existing site loaded 4 weights — 300, 400, 500, 600). Phase 1 ships only 400 + 600. Reduces font payload by ~30%.
- All sizes specified in `rem` (with px reference) so users who set custom browser font-size scale proportionally.
- `font-display: swap` mandatory; Astro Fonts API handles preload of Playfair 700 + Inter 400 (the LCP-critical pair).

**Heading hierarchy contract (load-bearing for AI-search per PITFALLS #5):**
- Exactly one `<h1>` per page.
- Strict H2 → H3 nesting; no skipped levels.
- First 150 words of every page contain the page's substantive answer (no "Welcome to my site" preambles).

## Color

**Carry forward the existing cream/charcoal/green/gold palette** with two surgical fixes for WCAG AA compliance, plus a full dark-mode set defined for `prefers-color-scheme: dark`.

**60/30/10 split (locked for Phase 1):**
- 60% cream (`--color-cream`) — page background and dominant surface across every page
- 30% cream-card (`--color-cream-card`) — the four homepage tiles, the footer band, the nav strip backdrop, About-page headshot frame, Colophon table rows
- 10% green (`--color-green`) — accent reserved-for list below

**Accent (green) reserved for, exhaustively:**
1. The single "Get in touch" hero CTA button (background `--color-green`, text `--color-cream`)
2. Inline links inside body prose (text color only — no underline-by-default; underline appears on hover/focus)
3. The brand wordmark `<span>` (the "Bridge" of "Cross The Bridge" in the nav logo, mirroring existing site)
4. Focus rings on all interactive elements (`outline: 2px solid var(--color-green); outline-offset: 2px;`)
5. Section markers (small ▸ glyph at H2 level on About page) — optional, planner discretion
6. RSS icon when added (Phase 2)

**Accent NEVER appears on:** project-card backgrounds, body backgrounds, large surfaces, decorative bands, headlines, any text larger than 18px (use charcoal for headlines).

**Gold (`--color-gold` / `--color-gold-light`) reserved for, exhaustively:**
1. Hero ornament (subtle gold glow at bottom of hero, mirroring existing radial gradient — keep it understated, opacity ≤0.12)
2. Section-divider rules below H1 on About page
3. Inner ring of focus state on green CTA (`outline: 2px solid var(--color-green); box-shadow: 0 0 0 4px var(--color-gold-light);`)

**Gold NEVER used as:** text, icon fill, link color, button text, button background, border on interactive elements.

**No second semantic color (no destructive).** Phase 1 has zero destructive actions: no delete, no logout, no irreversible CTAs. The contact CTA is benign. If Phase 2 introduces newsletter unsubscribe, declare destructive then.

**Color discipline (load-bearing):** No hard-coded hex values anywhere in component code. All colors flow through tokens. CSS-variable indirection is the contract.

### 2. `Nav.astro`
- **Layout:** Fixed top, full-width band, height 68px desktop / 56px mobile, backdrop `--color-cream-card` at 92% opacity with 12px backdrop-blur (matches existing aesthetic).
- **Contents (left → right):**
  - Brand wordmark: "Cross The <span class='text-green'>Bridge</span>" — Playfair Display 18px / weight 600. Links to `/`.
  - Nav links (desktop, ≥768px): Home / Projects / About / Contact / Colophon — Inter 14px, weight **600**, color `--color-charcoal-mid`. Hover: `--color-charcoal`. Active route: `--color-green` (no background, just color shift). (Weight 600 is one of the two loaded Inter weights — using 500 would force the browser to synthesize from 400/600 since 500 is not loaded; visual difference at 14px is imperceptible and 600 ships in the bundle either way.)
  - Mobile (<768px): Brand wordmark + hamburger toggle (44×44 hit area, lucide `menu` icon, `aria-label="Open navigation"`, `aria-expanded` state).

### 5. `CtaButton.astro`

## Motion / Interaction Contract

**Default posture: minimal motion, instant feedback.** Generous-density Collison sites earn trust through stillness, not animation.

| Surface | Allowed motion | Duration | Curve |
|---------|----------------|----------|-------|
| CTA button hover | Background-color transition | 200ms | ease-out |
| CTA button active | `translateY(1px)` press affordance | instant | linear |
| Tile hover | Border-color transition + subtle background darken | 200ms | ease-out |
| Link hover (in body prose) | Underline appears | 150ms | ease-out |
| Mobile nav drawer | Slide-down 8px + opacity 0→1 | 220ms | ease-out |
| Theme-color change (light↔dark via system) | Browser-default | — | — |
| Focus ring | Instant (no transition — keyboard users need clarity) | instant | — |

**Banned motion:**
- Scroll-triggered fade-ins (parallax, scroll-snap, IntersectionObserver reveal animations) — reads as "marketing template" and violates the calm Collison aesthetic.
- Hero text typewriter, hero word-by-word fade, autoplay video.
- Cursor-following effects, mouse-trail particles.
- Sticky elements other than the top nav.
- Any animation longer than 300ms.

**`prefers-reduced-motion: reduce` contract:** All transitions above are wrapped in `@media (prefers-reduced-motion: no-preference)` blocks. With reduced-motion the user gets: no slide-down on the mobile drawer (instant open/close), no hover transitions (instant color change), no `translateY` press (instant click feedback). Border/color changes still happen — only motion is suppressed.

## Accessibility Contract (WCAG 2.2 AA, mandatory)

The Phase 1 success criteria require Lighthouse Accessibility ≥95 on home, About, and project pages. This contract makes that a default outcome.

| Rule | Implementation |
|------|----------------|
| Color contrast (text) | All body text ≥4.5:1, all large text (≥18.66px bold or ≥24px regular) ≥3:1. Verified table in §Color above. **`--color-muted` tightened from `#7A7060` (4.40:1) to `#6A6050` (5.58:1)** because `#7A7060` failed AA-body. **`--color-gold` flagged as decorative-only** because 2.03:1 fails text contrast on every surface. |
| Color contrast (non-text) | Interactive borders, focus rings, icons that convey state ≥3:1 against adjacent surfaces. Focus ring uses `--color-green` (8.79:1 on cream — over-spec). |
| Color is not the sole channel | Active nav state communicated by both color AND a 2px under-rule (`border-bottom: 2px solid var(--color-green)`). Outbound links communicated by both color AND an `external-link` icon. |
| Skip-to-main link | Present on every page, first focusable element, visible on focus, links to `#main`. |
| Heading hierarchy | One H1 per page, strict H2/H3 nesting, no skipped levels. Build-time check via `astro check` + manual audit at launch. |
| Alt text | Every `<img>` has `alt=""` attribute (decorative) or descriptive alt text (content). Astro `<Image />` enforces this. The headshot alt: "Wesley Pyburn — founder of Cross The Bridge." |
| ARIA labels | Hamburger toggle: `aria-label`, `aria-controls`, `aria-expanded`. Mobile nav: `<nav aria-label="Mobile navigation">`. Hero CTA: descriptive text, no aria-label needed. External links: `rel="noopener noreferrer"`, optional `aria-label="opens in new tab"` if the icon alone isn't enough. |
| Keyboard navigation | Every interactive element reachable via Tab in DOM order. Mobile drawer traps focus while open, restores focus to hamburger on close. Escape closes the drawer. No keyboard traps anywhere. |
| Focus indicators | All interactive elements show a visible focus indicator on `:focus-visible`. Default browser focus outline replaced with the green-ring + gold-glow contract. NEVER `outline: none` without a replacement. |
| Touch targets | Min 44×44px (WCAG 2.2 `2.5.5 Target Size`). Hamburger, mobile nav links, CTA button (48px tall via `--space-md` vertical padding) all measured. Hit area can extend invisibly past glyph via padding. |
| Dark mode | Respects `prefers-color-scheme`. Both modes verified ≥AA on body text and accent surfaces. No manual toggle in Phase 1 (per D-10 and A11Y-03). |
| `prefers-reduced-motion` | All transitions wrapped in `(prefers-reduced-motion: no-preference)`. |
| Language | `<html lang="en">` on every page. |
| Page title | Unique per page, ≤60 chars, ends with " — Cross The Bridge" suffix (homepage exception). |
| Form labels | n/a — no forms in Phase 1 (Contact uses obfuscated mailto). |
| Error identification | n/a — no forms. |

**Verification gate (CI):** Lighthouse runs informationally on Vercel preview deploys (no threshold gate per D-16), but a launch-blocking manual audit on home + About + one project page must show ≥95 Accessibility before Phase 1 ships.

## Contact Mechanism (D-13)

**Obfuscated mailto** — no form, no backend.

**Implementation:** ROT13 obfuscation on the email string, with a small inline script that decodes on click. Example pattern:
```html
<a class="cta-primary" href="#"
   data-user="jrfyrl"  data-domain="pebffgurnoevqtr.vb"
   onclick="this.href='mai'+'lto:'+atob(btoa(this.dataset.user.replace(/[a-zA-Z]/g,c=>String.fromCharCode((c<='Z'?90:122)>=(c=c.charCodeAt(0)+13)?c:c-26))))+'@'+this.dataset.domain.replace(/[a-zA-Z]/g,c=>String.fromCharCode((c<='Z'?90:122)>=(c=c.charCodeAt(0)+13)?c:c-26));"
   >Email Wesley</a>
```
(Planner can choose a cleaner pattern — Cloudflare-style decode, hand-rolled JS reveal, or a build-time random nonce. Contract is: bot-readable plaintext email never appears in the rendered HTML.)

**Display variant:** Show the email as visible text too (`wesley[at]crossthebridge[dot]io`) so users without JS can still copy it manually. The interactive button is the convenience layer.

**No-JS fallback:** If JS is disabled, the button is replaced (via `<noscript>`) with a styled paragraph showing the obfuscated email and instructions to assemble it.
